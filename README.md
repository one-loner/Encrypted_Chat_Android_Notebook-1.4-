# Записная книжка / Notebook 1.1.0

Нативный Android Studio-проект, Java, **Android 7.0+ / minSdk 24**.
compileSdk и targetSdk — 35. Application ID сохранён: `com.loner.encryptedchat`.
Это обновление существующего клиента: чаты, ключи, QR, вложения, языки и
зашифрованный экспорт сохранены. Название и иконка изменены на заметницу.

## Установка обновления

Устанавливайте `Notebook-1.1-debug.apk` поверх предыдущего APK, **без удаления
приложения**. APK подписан тем же сертификатом, что и выданная версия 1.0.
Подпись проверена, установка через `adb install -r` прошла успешно.

Если ваша установленная версия была собрана самостоятельно с другим ключом,
обновление также должно быть подписано вашим прежним ключом. Исходный закрытый
ключ подписи не включён в архив исходников. Не удаляйте приложение ради смены
подписи: удаление уничтожает Keystore-ключи и локальное хранилище.

## Сборка в Android Studio

1. Распакуйте исходники и откройте корневую папку проекта.
2. Установите JDK 17, Android SDK Platform 35 и Build Tools 35.0.0.
3. Дождитесь Gradle Sync и запустите приложение на Android 7.0+.

```sh
./gradlew assembleDebug
./gradlew testDebugUnitTest lintDebug
./gradlew assembleDebugAndroidTest
./gradlew connectedDebugAndroidTest
```

Windows: `gradlew.bat`. Debug APK находится в
`app/build/outputs/apk/debug/app-debug.apk`.
Для самостоятельных обновлений используйте тот же signing keystore, что и у
вашей установленной сборки. Для release — Android Studio → Generate Signed
Bundle / APK со своим постоянным ключом подписи.

Если Gradle не может загрузить UTP, уже собранные Android-тесты можно выполнить:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w com.loner.encryptedchat.test/com.loner.encryptedchat.IsolatedTestRunner
```

Тестовый runner изолирует файлы и настройки UI-тестов от пользовательских данных.
Он находится только в тестовом APK и не добавляет обхода входа в приложение.

## Вход и заметница

На стартовом экране **одно поле пароля**, без выбора режима:

- основной пароль открывает чаты;
- пароль заметницы открывает только заметницу;
- пустой/неверный пароль не открывает данные;
- после неудачных попыток применяется сохраняемая между запусками задержка
  повторного входа, до 30 секунд.

При самом первом запуске введите основной пароль от 12 символов. Его повторное
введение выполняется в отдельном диалоге подтверждения, а не вторым полем
стартового экрана.

Для создания заметницы: войдите основным паролем → Настройки → Задать пароль
заметницы. Выберите другой пароль от 12 символов, заблокируйте приложение и
введите его в общее поле входа. Совпадение основного и дополнительного паролей
отклоняется при создании и смене любого из них.

В заметнице доступны создание, редактирование и удаление заметок, смена её
пароля и блокировка. Заметки сохраняются автоматически после редактирования,
по кнопке «Сохранить» и перед уходом в фон/блокировкой. Удаление подтверждается.
Лимиты: 1000 заметок, заголовок до 200 символов, текст до 1 млн символов,
общий объём текста до 5 млн символов. Ошибки сохранения показываются пользователю.

Заметница использует отдельный `notebook.enc`, отдельный случайный мастер-ключ
и отдельный Android Keystore alias. Основной пароль не расшифровывает заметки.
Из основного режима нельзя открыть, сбросить или изменить существующую заметницу.
Смена её пароля доступна только внутри заметницы с подтверждением прежнего пароля.
Открытие одной области не открывает вторую. При уходе в фон обе блокируются.

Экспорт учётной записи чатов **не включает заметницу**: это разные области защиты.
Пароли не восстанавливаются. Удаление приложения удаляет и локальную заметницу.

## Серверы и SOCKS5

Настройки → Серверы → Добавить сервер:

- название;
- HTTPS-адрес папки или `index.php`;
- логин и пароль учётной записи, созданной администратором;
- переключатель «Включён»;
- необязательный SOCKS5: адрес, порт, логин и пароль.

Пример адреса: `https://chat.example.org/ec8/`. Сервер должен иметь сертификат,
которому доверяет Android. Используется основной режим
[index.php/web.html](https://github.com/one-loner/encrypted-web_chat_v1.2),
протокол проверен по коммиту `63c5cce3abfae81ebd42a9e46df8695fba0ef087`.
`guest.php` и старый интерфейс с сырыми AES-ключами не добавлены.

Настройки можно сохранить без сети. Есть отдельная проверка подключения.
Включённые серверы проверяются при открытии основного режима; чаты опрашиваются
раз в две секунды. Отключение не удаляет настройки, историю или ожидающие отправки.
Допускается до 16 настроенных серверов.

При добавлении сервер включается в состав существующих локальных чатов.
Состав каждого чата можно изменить кнопкой «Серверы чата». Новые чаты по умолчанию
используют все включённые серверы. Одинаковые название комнаты и ключевая фраза
объединяются в одну вкладку, даже если ключи имеют разные локальные имена.
Разные ключи при одинаковом названии дают разные вкладки с уточняющим именем ключа.

Изменение адреса или логина создаёт новую запись сервера и отключает старую:
источники старых сообщений и старые ожидающие отправки не перенаправляются
другому серверу/пользователю. Новый адрес добавляется в соответствующие чаты.
Изменение пароля/прокси сохраняет идентичность сервера и переподключает сеансы.

Если поля прокси пустые, соединение идёт напрямую, без системного прокси.
SOCKS5 поддерживает CONNECT, доменные имена с разрешением на прокси, IPv4/IPv6,
режим без авторизации и username/password. Адрес — IP или ASCII/Punycode hostname,
порт 1–65535. Для авторизации нужны оба поля, по 1–255 байт UTF-8.
Ошибки параметров, авторизации и подключения обрабатываются отдельно.
TLS/проверка сертификата HTTPS-сервера продолжают действовать внутри туннеля.

Настройки SOCKS5 и его секреты сохраняются **только внутри зашифрованного Vault**
и входят в зашифрованный экспорт. Глобальный `Authenticator` не используется.

## Отправка, резервирование и повторы

Каждая пара «сервер + вкладка» имеет собственные cookies/CSRF и PHP-сеанс.
У серверов независимые сетевые очереди. Сбой одного сервера не удерживает отправку
на остальных. Отправляется один AES-GCM-конверт на все выбранные включённые серверы.

Перед сетью сообщение и состояния получателей сохраняются в зашифрованной очереди.
При частичном сбое успешная доставка сохраняется, оставшиеся адресаты повторяются
с задержкой 2–60 секунд, пока основная область разблокирована. Отключённые серверы
и исключённые из чата адресаты приостановлены; после включения отправка продолжится.
При HTTP 401 нужна явная кнопка «Подключиться снова» или исправление настроек.

При неоднозначном результате запроса перед повторным POST проверяется история:
если исходный конверт найден, доставка считается подтверждённой без повторного POST.
Повтор использует тот же IV и ciphertext. У сервера нет idempotency API, поэтому
при сетевой гонке строго «ровно одна запись на сервере» гарантировать нельзя;
повторные копии в обновлённом клиенте отображаются один раз.

Идентификатор сообщения — SHA-256 декодированных `IV || ciphertext`, включая тег
GCM. Разные сообщения с одинаковым текстом имеют разные IV/идентификаторы.
Дополнительно новый payload содержит случайный `clientMessageId`, который не
мешает существующему `web.html`. Текст/время не используются для дедупликации.
Источники сохраняют serverId, серверный ID, отправителя, время и fileId.
Нажатие на подпись сообщения показывает источники и идентификатор конверта.

Переписка не синхронизируется скрыто после блокировки: ключи закрываются,
незавершённые задачи отменяются, очередь возобновляется после следующего входа.
При отзыве доступа на всех включённых серверах чата его отображение скрывается;
доступные остальные серверы продолжают работать.

## Расположение сообщений

Настройки → «Свои сообщения справа, остальные слева».
Настройка общая для всех чатов и сохраняется в прежних SharedPreferences.
При выключении остаётся прежнее полноширинное отображение.
Собственные сообщения определяются по учётным записям всех серверов и признаку
локально отправленного сообщения. Стороны физические: справа/слева.

## Ключи, QR и файлы

В разделе «Ключи» сохранены генерация 256-битного случайного секрета,
именование/переименование, показ фразы, QR на экране, сохранение PNG,
сканирование камерой и вставка JSON QR. Используемые чатами ключи не удаляются.

Генерируемый 32-байтный секрет преобразуется в Base64-ключевую фразу. Для
совместимости с веб-клиентом используйте одинаковые точное имя чата и фразу:

```text
chatId = lowercaseHex(SHA-256(UTF-8(chatName)))
key = PBKDF2-HMAC-SHA256(UTF-8(phrase), UTF-8("encrypted-chat-v1:" + chatId), 600000, 32)
message = AES-256-GCM(key, random 12-byte IV, UTF-8(JSON payload), 128-bit tag)
```

QR-формат сохранён: `format=encrypted-chat-key`, `version=1`, `type=phrase`,
`name`, `phrase`. QR/PNG содержит секрет: передавайте только участникам.
Текст и вложения до 5 МиБ шифруются до отправки; полученные файлы сохраняются
через системный диалог. Чаты переключаются свайпами и кнопками названий.

## Хранилище, миграция и резервная копия чатов

Сохранены `vault.enc`, его Keystore alias `encrypted-chat-vault-v1`, обёртка
случайного мастер-ключа паролем, PBKDF2-SHA256/600000 и AES-256-GCM.
Внешний контейнер дополнительно зашифрован Android Keystore; запись — AtomicFile.
Пароли и ключи не сохраняются открытыми; экран защищён FLAG_SECURE,
автоматические backup/device transfer отключены.

При первом входе старый JSON schema 1 мигрирует в schema 2: одиночная учётная
запись становится сервером, чаты получают устойчивые ID, serverIds/outbox,
история — идентификаторы и источники. Ключевые фразы, ciphertext, названия,
пароль хранилища и настройки языка не меняются. Миграция атомарна и идемпотентна.

Экспорт/восстановление по-прежнему используют защищённый JSON с отдельным паролем
копии от 12 символов, AES-GCM и PBKDF2-SHA256/600000. В экспорт входят все серверы,
включённость, SOCKS5 и его секреты, чаты, ключи, загруженная история и очередь.
Старые копии schema 1 импортируются с миграцией. Новая копия schema 2 предназначена
для версии 1.1 и новее. Восстановление атомарно заменяет только область чатов,
сохраняя текущий основной пароль и независимую заметницу.

Лимит копии — 100 МиБ; снимок включает уже загруженную историю.
Ключи Keystore и локальные пароли не экспортируются. Язык и режим карточек
остаются локальными пользовательскими настройками, как язык в версии 1.0.

На время системного выбора файла/сканера QR сохраняется прежнее исключение
автоблокировки до 60 секунд. В остальных случаях уход в фон сразу блокирует данные.
Java не гарантирует обнуление неизменяемых строк в памяти; аппаратные свойства
Keystore зависят от устройства, как и в предыдущей версии.
